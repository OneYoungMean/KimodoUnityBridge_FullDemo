# 通用执行约定

[English](common.md)

本文是 [common.md](common.md) 的中文版本，是根目录 Skill 当前使用的共享执行约定。它以一个循环替代原来的四阶段手册，并保留历史识别与比较流程中有用的证据规则。在同一动画任务中，Kimodo 命令和 Unity／项目 API 是地位相同的实现路径。

## 范围与任务分流

处理 Humanoid 动画片段（Clip）、生成用姿态（Pose），以及门、球、武器等由 Transform 驱动的简单道具。Animator Controller、状态机、游戏逻辑脚本、复杂绑定、四足角色、载具和物理制作不属于本工作流。最终逐帧表演润色可能需要动画师。

根据用户期望的结果选择主要路径；存在依赖关系的子任务可以组合使用不同路径：

| 请求 | 路径 |
|---|---|
| 检查或比较现有动画 | 解析并评估现有 Clip；跳过生成和源动画编辑。 |
| 生成新动画 | 定义标准，生成候选，再进行评估。 |
| 改进、续接或重定向现有 Clip | 检查源动画，选择编辑或生成路径，并将派生产物与源动画比较。 |
| 制作角色与道具交互动画 | 协调角色动作、道具运动、接触事件和 Timeline 集成；验证组装后的完整结果。 |
| 意图不明确 | 先检查可用上下文；只对尚未解决且会实质改变结果的选择提问。 |

## 命令入口与状态

公开的 Editor 入口如下：

```csharp
string schema = KimodoUnityBridge.Command.command_dispatcher.GetCommandDefinitionsJson();
string result = KimodoUnityBridge.Command.command_dispatcher.Invoke(commandName, argumentsJson);
```

选择工具前，先规划在 Unity 中最终可见的完整结果。Kimodo 命令、Unity Editor API、Timeline API、AnimationClip／AnimationCurve API、运行时 API 和项目本地工具，都是同一执行循环中的平等路径。遵守用户指定的路径或工具限制；通过 API 成功完成操作，不能证明被绕过的 Kimodo 命令路径有效。选择 Kimodo 命令或参数前，读取实时 schema 或 `kimodo.help`。使用协议中的命令名，不使用内部 C# 处理函数名。通过 Unity CLI 操作时，在已连接的 Editor 中执行 dispatcher。命令帧率为 60 FPS；每个字段应按文档规定，使用 Clip 相对帧或 Timeline 全局帧作为基准。为每个子任务记录 `子任务 → 实现路径 → 产物 → 验收检查`。如果某项操作更适合使用被允许的 Unity 或项目 API 表达，就直接使用该 API，并记录所用路径。

[`Command/help.json`](../Command/help.json) 是仓库中的参考文档，不能替代已连接 Editor 的实时 schema。

通过 `scene.context` 和相关命令返回结果解析角色、Clip、Timeline 和 Session 引用。使用返回的句柄，不要根据显示名称猜测。资产路径只适用于明确接受路径的字段，不能替代所需的场景句柄或 `{track,index}` 引用。

当前 Unity 场景、Timeline 和 Kimodo Session 构成可编辑的工作管线。Agent 可以切换上下文，也可以通过插入轨道、Clip、绑定或同步的道具运动扩展现有 Timeline。默认保留已有轨道和 Clip；优先添加轨道或创建派生 Timeline，而不是重写或重建现有内容。只有任务确实需要时才修改现有内容，并先保留可恢复的原始版本。编辑后，在目标 Timeline 中验证当前场景／Session、轨道绑定、Clip 范围和同步关系。

需要移除内容时，将受影响文件及对应的 Unity `.meta` 文件移入就近的 archive 目录，并检查受影响的引用。

坐标空间约定：

- 公开命令中的位置和目标（`root`、`effector`、`pose.set` 和 `pose.test` 的目标）均使用 Unity 世界空间。
- 点约束中的 `root.rotation` 和 `effector.*.rotation` 接受以度为单位的欧拉角 `[x,y,z]`。每个 Transform 必须提供位置和／或旋转；省略的通道保留采样值。命令根据 root 选择 Root2D，根据 root + effector 选择 Effector，根据 pose 以及可选的 root／effector 选择 FullBody（通过 IK 求解）。空输入或只有 effector 的输入无效；同一命令中的重复帧会被拒绝。
- `animation.analyze.root_trajectory` 返回世界空间数据。被分析的 Clip 从第 0 帧开始，因此其轨迹零点就是该命令使用的世界空间参考点。当 `animation.generate` 使用其 `root_path` 时，生成流程会基于目标角色在世界空间中的根位置和水平朝向，对该世界空间路径做一次解析。
- 关节局部旋转和相机专用字段继续使用各自文档规定的空间；世界空间规则适用于位置和目标字段。

任务开始时，维护一份简洁的循环状态：

```text
任务路径与当前检查项
意图、明确要求、假设和未知项
项目／场景／Session、角色／对象引用及相关工具版本
规划中的 Clip 及其依赖关系
子任务与实现路径的对应计划，以及已生成的资产／轨道
验收标准与允许的动作语义备选项
已确认的 Pose、root、effector、路径和对象证据
候选记录：request_id、animation_id、seed、prompt、constraints、analysis_id
各项标准的结果：verified、failed 或 unknown
修订历史、最佳候选、尝试预算与无改进次数
各子任务的能力依据和未解决的选择
```

不要另建一套公开状态协议，也不要复制完整的场景／分析载荷。通过持久化的 Session 历史和返回的 ID 查找候选。

## 路径与检查约定

使用上面的任务分流。schema 查询和场景检查等只读探索，可以先于路径确认。生成或编辑前，明确目标对象或 Clip、预期产物、相关标准及依赖关系。默认保留原始版本并创建派生产物；直接沿用用户已有的授权，不重复询问。

对每个子任务，区分实现路径及其能力依据：

| 能力 | 所需依据 |
|---|---|
| 当前 Kimodo 命令 | 存在于实时 schema 中；还需检查当前场景和运行时前置条件。 |
| Unity 或项目 API 路径 | 检查相关 API 及其集成方式，再在当前项目中验证产物。 |
| 规划中的能力 | 尚在提议阶段的命令或集成；不得调用，也不得声称已经实现。 |
| 不可用路径 | 已检查相关命令和 API 路径，确认它们无法在当前环境中完成该操作。 |

schema 中存在某接口，只能证明接口存在，不能证明其产物满足任务要求。标准结果（`verified`、`failed`、`unknown`）以及是否交接给动画师，都应与能力是否可用分开判断。

检查项可以重新进入；跳过与当前路径无关的工作：

| 检查项 | 执行依赖工作前所需的证据 |
|---|---|
| 意图与范围 | 用户要求的结果、明确限制、会影响结果的选择，以及无实质影响的假设。 |
| 引用与场景状态 | 目标项目／场景、角色和所需的 Avatar、源 Clip、Timeline／Session，以及相关道具的 Transform、轴心和包围盒。 |
| 约束与标准 | 已确认的坐标／帧基准、交互事件、适用容差，以及每项必要结果的可行检查方法。 |
| 执行 | 已提交的输入与 ID、最终状态或 API 产物，以及实际评估的 Timeline 绑定／范围。只检查的任务复用现有 Clip。 |
| 验证 | 与候选相匹配的测量／图像，以及必要时的播放证据；发生变化时，重新检查受影响的依赖项。 |

先通过现有上下文补齐缺失事实。只有尚未解决的不同选择会实质改变用户要求的结果时才提问；等待回答期间，暂停依赖该答案的生成／编辑，并继续独立工作。缺少验收证据的项目仍为 `unknown`，不能通过将任务视为通过来跳过。仅仅进入一个检查项，不需要额外确认。

## 响应与异步规则

- 读取业务字段前，先检查顶层 `ok`。
- 命令错误使用 `ok=false` 和 `error={code,message,details?}`。
- 一次轮询成功时，任务 `status` 仍可能是 `failed` 或 `canceled`；应报告该最终状态及其错误。
- 保存完整、准确的 `request_id`；按固定间隔轮询，直到进入最终状态或达到限定超时。
- 这适用于所有返回待处理 `request_id` 的异步命令，包括 `server.install` 和 `animation.generate`。轮询超时意味着任务仍待处理，不代表失败或已取消；保留 ID，以便恢复查询。
- 不要重复提交仍在运行的请求。只有任务应当停止时才取消。
- 将警告和非阻断检查视为需要查看的证据。
- 保留已完成的 Clip，修订时创建派生产物。

## 从意图到标准的循环

只执行所选路径需要的工作；检查／比较任务不生成动画，也不编辑源动画：

1. 从当前场景解析参与的角色和对象。明确可见结果、动作顺序、接触点、时长和结束状态。说明假设。
2. 识别可独立检验的动作节拍。只有局部修订或续接需要确实值得拆分时，才拆成多个 Clip；不同节拍不自动等于不同 Clip。记录角色 Clip、道具运动和 Timeline 绑定之间的依赖关系。
3. 选择相关标准，区分必要约束和质量偏好。标准可以涉及语义、空间、时间、接触、结构、视觉或播放。说明可观察的检查方法，必要时给出容差；不要自行发明通用分数或通过阈值。
4. 收集所需的最少证据：`scene.context`、`pose.get`、`pose.test`、`transform.capture`、已有 Clip 的分析结果，或已确认的对象 Transform。直接捕获关键帧时，向 `transform.capture` 传入 `character_path` 和绝对帧 `timeline_frame_60`；使用现有 External Pose 时，继续使用其 `{track,index}` 引用。进行视觉验收时，添加 `camera: {"mode":"scene","path":"Main Camera","auto_frame":true,"resolution":[1280,720]}`；这只在内存中克隆并调整场景相机，为捕获关闭由 HDR／Volume 引起的过曝，并恢复源相机。保留结构化四视图／位置证据作为客观补充。使用 `pose.test` 测量任意采样 Pose 中实际的 Humanoid 关节位置，并与接触目标比较；使用 Effector 约束生成后也应如此。生成时的 pose／effector 安全预检，只在同一个点约束明确同时包含 `pose` 和 `effector` 时运行；root + effector 约束跳过该检查；只有 effector 的输入无效，因为它缺少明确的 root 上下文。这类预检警告不阻断执行，也不能替代姿态实测结果。不要将每项观察都转成约束。
5. 需要生成时，根据已确认的场景证据或明确要求，构造简短的语义提示词和受支持的结构化约束。精确的根位置、朝向、Pose、手／脚目标、循环、时长和续接数据，在支持时放入 Kimodo 字段；对象曲线、Timeline 轨道、绑定及其他资产编辑，则交给适合的 Unity 或项目 API。复用 `pose.get` 的 `{track,index}` 前，先检查其结果；未经检查的场景 T-pose 或 Clip 名称，不是已确认的续接来源。按依赖顺序生成 Clip，后续 Clip 使用已评估的前序结束状态。
6. 只有确有需要时才生成或编辑候选，轮询异步请求，并保留 ID 和提交的设置。API 产物没有 Kimodo ID 时，保留实际资产／轨道引用。检查路径以现有产物为评估对象。
7. 先评估相关硬性要求，再按需检查结构、场景交互和播放／质量标准。使用 `animation.analyze` 评估 Humanoid Clip；使用求值后的场景测量和适当 API 检查道具／Timeline。作出视觉结论前，先打开返回图像。接受某项标准前，核对下文规定的证据与产物对应关系。
8. 只有存在多个候选或用户要求比较时，才进行候选比较。采用相同条件，逐项判断标准。
9. 有证据表明某项标准失败时，只修改相关输入，并创建派生候选。缺少证据时，补充证据或报告 unknown；不要盲目重试。
10. 应用下文的停止与交接规则。没有新证据或输入变化时，不要重复提交完全相同的请求。

## 识别约定

识别是受约束的证据处理操作，不是新意图的来源。需要区分动作语义时，由调用方提供语义备选项。不得根据文件名、Clip 名称、候选顺序、ID 或视觉显著程度推断。

只执行以下集合中与任务相关的识别项：

```text
visual: trajectory_shape, action_semantics, visual_motion_quality, contact_pattern
structured: loop_endpoint, keyframe_heading, trajectory_turn,
            trajectory_length, phase_track, endpoint_pose, motion_profile
```

视觉结果刻意限制为较小的取值集合：

```text
trajectory_shape: closed_loop | open_path | near_static | unclear
visual_motion_quality: smooth_appearance | visible_break | unclear
contact_pattern: alternating | left_dominant | right_dominant | unclear
```

每个识别项都返回取值、置信度和证据。图像无法辨读、字段缺失、证据冲突，或结论依赖尚未观察的播放过程时，返回 `unknown` 或 `unclear`。`smooth_appearance` 只描述静态图形没有断裂，不代表播放流畅。结构化轨迹值必须来自返回的具名字段，不能通过像素估算。

比较动作语义时，只使用调用方提供的备选项，以及阶段／姿态／接触证据。一次偶然接触或一个锚点帧，不能证明所需阶段存在。无法区分备选项时，保留 `unknown`。

## 比较约定

对每个候选分别分析和渲染，使用相同的图像请求、分辨率和证据流程。比较前核对候选与图像的对应关系。只比较任务已声明的标准，例如语义正确性、轨迹连贯性、足部接触、必要阶段覆盖、必要 Pose 覆盖、表现力度、端点连续性，或已声明的相邻 Clip 过渡。

每项标准报告 `candidate_1`、`candidate_2`、`tie` 或 `unknown`，并附简短理由和证据。不要将分数、票数、幅值、位移、接触次数或选取的帧数相加来计算总冠军。只有目标标准与证据足以构成决定性差异时，才优先选择某个候选；否则报告无法可靠区分或证据不足。

## 证据边界

每项验收结论都应保留简洁的来源记录：

```text
被评估的候选／源资产，以及提供时的 request／animation／analysis ID
项目、场景、Session、目标 Timeline 及其 Clip／轨道绑定
采样帧或区间、帧基准、分析／渲染设置
相关角色／道具的 Transform、偏移和源资产状态
返回的证据路径或测量字段、标准结果及限制
```

使用已有 ID 和 Session 历史，不重复复制载荷。工具未返回 ID 时，引用实际资产、帧和证据路径。复用证据前，确认被评估的来源及相关场景／Timeline 状态仍然一致。未发生变化的依赖项可以复用证据；角色 Clip 变化会使依赖它的道具跟随采样失效，绑定、偏移或道具状态变化会使受影响的交互证据失效。集成后重新运行这些检查。其他候选、旧 Timeline 或相机取景错误的截图，不能作为验收依据。

分别报告以下证据：

- **视觉**：已打开图像中实际可见的内容。
- **结构化**：命令返回的实测字段。
- **播放**：实际播放或受支持的运行时检查中观察到的内容。

静态图片不能证明速度或加速度平滑、没有滑步、没有跳变，或播放连续。受支持的时序测量可以在其采样限制内证明某项具体数值性质，但不代表已经观察完整播放。某项标准缺少证据时为 `unknown`，不等于失败。采样得到的关节距离只能证明该采样点的关系，不能证明手指握持、碰撞间隙或整个区间持续接触。

选择修订方式前，先归因：引用／前置条件无效，或请求／协议错误，属于工具链失败；角色产物已完成但不满足标准，属于生成质量失败；道具运动、绑定、偏移或同步错误，属于集成失败；观察缺失、过期或不足以得出结论，属于证据缺口。多种类别可以同时存在。重复生成不能修复协议错误或证据缺失。

## 修订与人工交接

内部使用针对性修订表：

```text
失败标准 → 支持证据 → 修改的输入 → 新候选 → 结果
```

进入生成／修订循环前，记录有限的候选数量或时间预算；用户提供限制时，使用用户的限制。本地默认允许一个初始候选，以及针对同一失败标准最多两次定向修订。这是成本控制的默认值，不是质量阈值；任务和已有授权足以支持时，可以选择其他有限预算。统计先前尝试和共用候选，不得通过重命名标准或重启循环重置预算。

满足以下任一条件时停止修订：必要标准通过；预算耗尽；在可比证据下，连续两次针对性尝试没有实质改进；完成相关检查后，没有被允许的路径能够执行必要操作；剩余缺陷需要人类艺术判断。根据已声明的标准定义改进；更换 Seed 或收到 `completed` 不是改进证据。缺少证据时应检查，而不是猜测性地重试生成。

保留满足硬性要求的最佳候选，拒绝使先前已通过要求退步的结果。如果没有候选满足硬性要求，保留最佳部分产物，并报告其失败／未知项，不要声称验收通过。不要重新生成无关且已通过的依赖项；重新检查修订实际影响的输出。缺少某条命令本身不是停止条件：先在用户的工具限制内检查相关包和 API 路径，再报告工具限制。如果无法取得必要工具，停止依赖该工具的执行，报告问题，并等待用户修复，不得改用 subagent 代替。

简单道具在已有能力范围内使用 Kimodo 命令，必要时使用 Unity API 制作 Transform 曲线、Timeline 轨道或手部挂接。通过共用接触帧、偏移、Timeline 范围和证据 ID，使道具始终与角色候选对应。同时验证角色姿态和对象运动；API 路径确实不可用时，将对应标准标为 unknown，并说明限制。

## 结果报告

明确选定的 Clip／资产及目标 Timeline。将必要标准逐项报告为 `verified`、`failed` 或 `unknown`，每项附上对应证据和相关限制。区分请求被接受、任务进入最终状态、角色 Clip 验收通过，以及完整交互验收通过。必要项仍为 unknown 时，不得声称已经完成完整验证。

概述针对性尝试、最佳结果、失败类别，以及实际停止原因。仍有剩余工作时，明确受影响的区间、身体部位、曲线、绑定或缺失证据，并给出具体下一步。工具链修复或证据缺口不一定需要交接给动画师；只有确实需要动画师的工作才做此类交接。

只有出现相关症状时，才查阅 [`known-issues.md`](known-issues.md)。其中记录的是观察结果和可选绕行方法，不是强制步骤或停止规则。归档手册仅供历史参考，不是当前执行指令。
